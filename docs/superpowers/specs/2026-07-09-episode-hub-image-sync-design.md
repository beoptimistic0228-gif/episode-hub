# Episode Hub 이미지 공유 (클라우드 드라이브 동기) 설계

- **작성일**: 2026-07-09
- **대상 앱**: `episode-hub/` (레포 분리 후에는 신규 앱 레포에서 구현)
- **커밋 scope**: `episode-hub`

## 1. 배경 · 목적

현재 에피소드의 **글자 내용**(`.md`/`.json`)은 git으로 PC끼리 잘 공유된다(무료·버전관리). 그러나 **이미지**(SKU 렌더 `renders/<정규화카테고리>__<row>.png`, 무드보드, 최종 이미지 등)는 **의도적으로 gitignore** 되어 있어 다른 PC로 넘어가지 않는다(메모리 백로그 "이미지 공유(LFS/클라우드)"). Owner가 여러 PC에서 콘텐츠를 만들 때 그림이 안 넘어와 불편하다.

목적: **글자는 지금처럼 git 유지, 이미지만 클라우드 드라이브 동기 폴더로 공유**한다. git 레포는 드라이브에 넣지 않는다(git↔드라이브 동기 충돌 위험). 앱이 "동기되는 로컬 이미지 폴더"를 가리키게 하여, OS(드라이브 클라이언트)가 PC 간 동기를 담당한다.

## 2. 확정된 결정 (brainstorming)

1. 공유 대상 = **이미지만**(글자·상태는 git 유지).
2. 방식 = **클라우드 드라이브 동기 폴더**(코드 최소·기존 드라이브로 무료). 선택: **Google Drive**. 단, 구현은 **드라이브 종류에 무관**하게 "동기되는 로컬 폴더 경로"를 가리키는 방식(Dropbox/OneDrive도 동일).
3. **PC마다 이미지 폴더를 1회 선택**(경로가 PC마다 다름 — 지금 orchestrator 폴더 고르는 것과 동일 패턴). 폴더 내부의 하위 구조는 동일해 드라이브가 자동 동기.
4. **레포 분리와는 별개 spec.** 앱 기능이므로 레포 분리 후 **신규 앱 레포에서 구현**(순서: 분리 → 본 기능).

## 3. 최종 상태

- **이미지 저장 위치** = 앱 설정의 `imageRoot`(= 사용자가 고른 Google Drive 동기 로컬 폴더, 예 `G:/My Drive/nakgwan-images` 또는 `C:/Users/<id>/My Drive/...`).
- **이미지 경로 구조**(PC 공통) = `<imageRoot>/<episodeId>/<상대경로>` — 상대경로는 지금 에피소드 폴더 내 이미지와 동일 규칙(예 `renders/<정규화카테고리>__<row>.png`). 루트만 PC마다 다르고 하위는 동일 → 드라이브 동기로 모든 PC가 같은 그림.
- **git 레포 에피소드 폴더** = 글자(.md/.json)만. 이미지는 레포에 두지 않음(기존 gitignore 대상이 아예 다른 폴더로 이동).
- **동작 흐름**: 앱이 렌더 이미지를 저장하면 `imageRoot` 아래에 기록 → 드라이브가 다른 PC로 동기 → 그 PC의 앱이 `imageRoot`에서 읽어 표시.

## 4. 앱 변경 (touch points)

1. **설정(`imageRoot`)**: `hub-config.json`(userData, per-PC)에 `imageRoot` 추가 + "이미지 폴더 선택" 다이얼로그(기존 `config:pickRoot` 미러). 미설정 시 이미지 기능만 비활성(글자·나머지는 정상).
2. **경로 헬퍼**: `resolveImagePath(imageRoot, episodeId, rel)` — `<imageRoot>/<id>/<rel>` 안으로 고정(경로 탈출 차단, `safeEpisodePath` 패턴 재사용). `assertEpisodeId` 경유.
3. **저장(`saveRender`)**: 저장 대상 = 레포 에피소드 폴더 → **`imageRoot`**. 드롭 저장(renderers drop)도 동일.
4. **표시(`hub://` 프로토콜)**: 이미지 요청을 **`imageRoot`에서 해석**(현재 `safeEpisodePath(repoRoot,...)` → `resolveImagePath(imageRoot,...)`). imageRoot 미설정/파일 미동기 시 **404를 우아하게**(깨진 이미지 대신 "아직 동기 안 됨" 플레이스홀더 신호).
5. **파일 목록(`scanEpisodeDetail`)**: 이미지 종류(FileEntry kind 'image')를 **`imageRoot`에서도 스캔**해 목록에 반영(글자 파일은 레포에서). imageRoot 미설정이면 이미지 목록 빈 상태.
6. **미동기 견딤**: Google Drive "온디맨드"로 아직 안 받아진 파일 → 존재하지 않음으로 처리(크래시 금지, 플레이스홀더/재시도 여지).

## 5. 기존 이미지 1회 이관

- 현재 이 PC의 레포 에피소드 폴더에 있는 gitignored 이미지들을 **`imageRoot`의 동일 하위 구조로 1회 복사**(스크립트 또는 앱 버튼). 이후 드라이브가 다른 PC로 동기.
- 복사 후 레포 폴더의 옛 이미지 사본은 gitignore라 무해하지만, 혼선을 줄이려면 정리 가능(선택).

## 6. 검증

- **단위**: `resolveImagePath` 경로 탈출 차단·정상 결합. `saveRender`가 `imageRoot` 아래에 쓰는지(픽스처 imageRoot). imageRoot 미설정 시 이미지 기능 graceful.
- **기능(단일 PC로 동기 시뮬레이션)**: 앱에서 이미지 저장 → 설정한 `imageRoot`에 파일 생성 확인 → `hub://` 표시 해석이 `imageRoot`를 읽는지 → 미존재 파일에서 앱이 안 죽는지.
- **실제 2-PC**: (Owner) 한 PC에서 렌더 저장 → Google Drive 동기 → 다른 PC 앱에서 그림 표시 확인.
- 기존 e2e/단위 회귀 없음.

## 7. 리스크 · 열린 질문

- **드라이브 클라이언트 의존**: Google Drive 데스크톱 앱이 실행·동기 중이어야 함. 꺼져 있으면 최신 아님(글자·상태는 여전히 git으로 안전).
- **동기 지연·온디맨드**: 방금 저장한 그림이 다른 PC에 즉시 없을 수 있음 → 앱은 "아직 없음"을 견디고 나중에 표시.
- **PC별 경로 상이**: `imageRoot`가 PC마다 다름 → per-PC 설정으로 해결(하위 구조는 공통).
- **동시 편집 충돌**: 같은 이미지 슬롯을 두 PC에서 동시에 저장하면 드라이브 충돌 사본 생성 가능(개인 2-PC·순차 작업이라 실사용 위험 낮음).
- **레포 분리 순서 의존**: 본 기능은 신규 앱 레포에서 구현(분리 완료 후). 분리 전 착수 시 콘텐츠 레포에서 하고 분리와 함께 이동해야 해 비효율 → 분리 먼저 권장.
- **이미지 위치 이원화 과도기**: 이관 완료 전까지 일부는 레포·일부는 imageRoot일 수 있음 → 이관을 초기에 1회 확실히.
